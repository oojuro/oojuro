# Exact literal cache prototype

This is prototype source work on a separate topic, with scoped correctness and small-corpus diagnostics below. It is not a release, a stable storage format, or a latency/storage claim. Source wire 0.1, Event profile 1 and their frozen vectors are unchanged. Existing create APIs retain their existing disposable layouts.

`Builder::create_positional` and the neutral `EventBuilder::create_positional` explicitly request disposable layout 3. Its authenticated identity is `OJPROJ03`; the descriptor must agree with that identity and contain a position root. Layouts 1/2 retain their encodings and remain readable. Older readers refuse layout 3; callers rebuild this disposable cache using a compatible reader.

The additional encrypted tree records exact byte offsets of maximal alphanumeric/underscore runs and maximal separator runs. Case, Unicode, whitespace, punctuation and NUL bytes are preserved. Equal position lists share row masks inside aligned 256-row fragments. A fragment holds at most 4096 logical positions and 28 KiB of encoded data; frequent runs in one row can span fragments.

A phrase whose first and last characters are word characters can receive a complete proof by intersecting raw-run identities and their exact relative byte offsets. This preserves the existing phrase boundary rule, including underscores and Unicode. Other phrases retain exact cached-original validation. A streamed proof limits the number of runs to 128, its conservative decoding allowance to 8 MiB, and its work to eight million candidate-position/bounded-binary-search units. A missing complete proof or exhausted allowance falls back to exact text. Malformed/authentication/EOF failures return errors rather than partial results.

The proof supplies candidate row masks to exact TF-bitplane sums and the existing global statistics/model arithmetic. Literal score bounds use independent minimum length and maximum TF only because literal TF gain is independent of length. Final scores still use the unchanged scorer; there is no shard fusion or approximate top-k. Original materialization still fetches caller-supplied authoritative originals and verifies every field and exact text digest. The neutral event adapter continues to omit non-UTF8 data from text indexing while those bytes remain readable in the source.

Construction rereads derived original blobs to create a bounded external sort. Incremental refresh adds only new run positions and preserves retired-row masks in the current numeric view. Existing logical all-build disk admission and observed allocated-byte metrics cover the added files; they are not filesystem quotas. No new retained cache policy is introduced, but position pages compete for the existing page cache and query decoding adds transient work.

Original text is still present for complete fallback support. The position tree adds bytes. Qualification must report actual source plus index bytes, build scratch/logical and allocated peaks, file counts, retained estimates, process RSS, cold reopen, mixed/varied queries, dense literals, raw/Zstd and incremental/encrypted cases. No one-third-space claim is justified by this prototype.

Source/release qualification for the frozen base and followups appears below. The cases cover raw/Zstd, Unicode/separators, filters, retire/append/reopen, dense scoring, fallback authentication and refusal before original callbacks. The final combined current-main/compact/numeric-group/literal gate remains pending; small-corpus diagnostics alone do not qualify consumer adoption.

A separate join prototype replaces the cross-product of groups and offsets with sparse offset-to-row-mask maps. Each map admits at most 8192 starts before inserting, with two maps charged at 128 bytes per entry (2 MiB maximum), in addition to the 8 MiB decoded-fragment allowance. It clips later position lists to the range of possible starts and preserves whole-proof fallback on work/map refusal. This changes query work only; cache bytes remain unchanged. Its focused checks and 1000-row timings are recorded below; larger-scale work remains unqualified.

A later storage prototype writes position-block codec 2: sparse row offsets for masks of at most 28 rows and canonical positive delta-varints for positions. It retains an explicit codec-1 reader. A new authenticated `position_codec: 2` descriptor requirement makes older prototype readers refuse at open; unknown requirements or an undeclared codec refuse before original callbacks. Layouts 1/2 omit the optional descriptor field and preserve their serialization. The layout remains explicitly disposable and source wire/profile bytes are unchanged. Decode admission now includes bounded group containers and varint expansion before allocation. Its focused qualification and 1000-row storage/latency measurements are recorded below; larger-scale qualification remains open.

The [full base/focused join receipt](qualification/juro-exact-literal-prototype-2026-10-25.json) records 208 passing engine tests and 8 rank tests at `f0b540b`, then 5 codec/map and 3 end-to-end exact-oracle cases plus strict Clippy/source-fenced release proof at `37cfb85`. Ten existing engine tests remain ignored. The combined current-main/compact/numeric-group/literal source still needs its final complete gate before consumer adoption.

The [38 actual-file observations](benchmarks/JURO_EXACT_LITERAL_1K_DRAFT_2026_10_25.json) cover 1000 varied synthetic events (998 UTF-8 rows indexed), raw/Zstd derived caches and ten clients. Three observations of dense phrase p95 with the final-result cache bypassed were 188–237 ms raw / 217–242 ms Zstd on layout2; layout3 with the original cross-product join measured 59–74 / 52–71 ms, and the bounded offset-map join measured 30–34 / 30–40 ms. Exact signatures matched across every query/layout/codec/runtime. Result reuse and reopen appear separately in the raw receipt; this is a small local diagnostic, not larger-scale or hosted acceptance.

Storage is adverse: the exact source is 1,935,784 bytes, and layout2 index bytes are 2,368,598 raw / 830,599 Zstd. Layout3 grows the index to 5,567,149 / 4,029,141 bytes, for combined source-plus-index totals of 7,502,933 / 5,964,925 bytes. Observed retained allocations are 5,578,752 / 4,038,656 bytes; source allocation is 1,937,408 bytes. Layout3 construction took about 1.36 s, with observed allocated build peaks of 15,818,752 / 14,376,960 bytes and process RSS around 22 MiB. The full retained policy estimate was about 25.3 MB. All owned source/index data copies from this phase were removed after the matched comparison. Position storage and larger-scale query work remain open optimization targets.


The [codec-2 focused gate](qualification/juro-literal-position-codec-2026-10-25.json) passed at `353d078`: six codec/map tests and five end-to-end cases, strict Clippy, and source-fence-2 release proof with every mutable compiler artifact rebuilt. It includes legacy codec-1 reads, mixed-codec incremental generations, canonical sparse/delta refusal and required-feature/before-callback refusal. The [28 actual-file observations](benchmarks/JURO_POSITION_CODEC_1K_DRAFT_2026_10_25.json) also assert that the previous prototype executable refuses the new authenticated descriptor at open, and the new executable reads the legacy cache. All successful exact signatures match; both expected refusals and final data-copy cleanup are recorded.

On this same 1000-row source, codec 2 reduces the positional index from 5,567,165 to 3,069,068 bytes raw and from 4,029,152 to 1,531,048 bytes Zstd. Total source-plus-index bytes are 5,004,852 and 3,466,832. Retained allocations are 3,080,192 and 1,540,096 bytes. These are still larger than layout2. Dense p95 ranges over three matched ten-client observations are 39–47 ms legacy versus 29–49 ms compact raw, and 34–41 versus 28–33 ms Zstd. The raw latency benefit is not established by this small sample. Build time remains around 1.36/1.40 s, observed build allocation peaks remain 15.82/14.38 MB because temporary row/sort data is unchanged, and process RSS remains around 22 MiB. Larger-scale dense queries, incremental/encrypted actual-file cases and the final integrated gate remain open.

A per-row range prototype is pending qualification after the 100k varied dense path opened cached originals. Each run group now clips offsets to the possible start range for its own row mask, avoiding separator work caused only by longer records. Two 256-entry arrays add 2 KiB of bounded transient state; row-mask work is charged to the existing eight-million-unit guard. Exact complete-proof fallback and cache bytes remain unchanged. Randomized exhaustive row joins and a heterogeneous-fragment budget oracle must pass before measuring it.

The followup also admits at most 16384 logical per-row starts before pushing, with conservative Vec growth/container allowance of 144 KiB. A group can choose between scanning its clipped positions and checking the smaller per-row start lists against bounded sorted positions. All row/start work remains charged to the original guard; refusing the optional lists retains the exact range-scan path. An additional oracle covers irrelevant positions inside each row span, which range clipping alone cannot remove.

A proof-mask reuse prototype is pending qualification. Exact raw needle hashes address complete unfiltered proof masks within the existing precharged 12 MiB term-cache policy, entry limits, singleflight, leases and eviction. No query text, authority decision or final rank result is retained. Admission precedes construction; failed/incomplete proofs retain ordinary exact fallback. Every query owns a mask copy before live/filter/driver refinement and still checks its fresh Binding, scoring statistics, original budget and selected authoritative originals. No retained cache policy is added or enlarged.

An integrated numeric-shape prototype is pending qualification: exact literal candidate masks can address the same bounded numeric groups used by scope-model queries, with a distinct raw-needle/term-set cache key. It uses the existing shared budget, preserves complete scorer fallback and the top-20 guard, recomputes global scoring statistics/weights per query, and retains no raw query text or authority decision. Case/spacing, weights, large-k fallback and retire/append/reopen must match the full oracle before measurement.
